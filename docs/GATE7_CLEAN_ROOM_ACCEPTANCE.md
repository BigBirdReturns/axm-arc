# Gate 7A clean-room acceptance: The Orchard at Low Tide

**Status:** creator-side candidate for the RODOH 1.0 generalization proof.

**Authority boundary:** this is an exact generic Arc. It is not a Godscar source plane, a bundled first-party cartridge, a Program of Record, or a new engine capability.

## Purpose

The clean-room proof asks whether a creator can produce a complete, portable world after the five first-party references without changing Arc implementation law. The candidate therefore uses unfamiliar civic-orchard vocabulary and the public generic Arc contract only.

The proof fails if it requires a change under `src/engine`, a registered source-plane entry, a cartridge-specific compiler, receiver fields, a hardcoded role vocabulary, a trust exception, or a first-party identity claim.

The editable source and executable cartridge are intentionally identical generic Arc documents. The manifest records exact file checksums, byte counts, cartridge identity, run integrity, engine version, generator command, and unknown namespaces.

## Unfamiliar authored vocabulary

The candidate introduces no first-party role or resource names.

- Roles: Graftwright, Tide Diver, Lantern Clerk, Rain Custodian.
- Resources: Civic Credit, Rootstock, Lanterns, Season Standing.
- Domain: civic orchard.
- State: water reserve, seed diversity, public memory, monopoly debt, season charter, and field census.

The five linked challenges are:

1. Count the Brackish Wells.
2. Negotiate the Graft Exchange.
3. Dive the Moon Cistern.
4. Replant the Ninth Orchard.
5. Publish the Next Season.

## Decision evidence

The candidate provides two distinct decision surfaces before resolution.

Roster composition changes projected margins because senior and junior founders carry different role and attribute profiles. Resource spending changes steadiness because early challenges expose different token ceilings and costs. These are authored ordinary Arc decisions rather than a hidden clean-room helper.

Success, partial, and failure outcomes all remain consequence-bearing. They alter the same bounded state definitions rather than resetting the campaign or substituting narrative-only consequences.

## Unknown memory

The cartridge carries `unfamiliar.garden-memory@7`. The changed run carries `holder.field-notes@1`. Neither namespace is interpreted by the engine. Both must survive validation, play, run construction, parse, export, and later World custody without normalization or loss.

## Malformed companion

`orchard-at-low-tide.invalid.arc.json` deliberately violates its first challenge roster bounds. Compatible tools must refuse it through ordinary Arc validation. They may not repair it, infer the intended roster, or install it as a trusted cartridge.

## Deterministic campaign acceptance

The accepted exact head must prove:

- source and executable Arc equality;
- stable `cart1_` identity and file checksums;
- exact changed-run integrity;
- complete campaign reachability across sixteen deterministic seeds;
- no stalls, max-cycle exits, access bypasses, or engine warnings;
- at least two materially different roster projections;
- malformed-artifact refusal;
- unknown cartridge and run memory preservation;
- complete Arc tests and production build;
- a clean artifact rebuild with no diff.

## Handoff to World

World receives the exact source, executable Arc, malformed fixture, changed run, manifest, and accepted digest from this train. It must import the cartridge through the ordinary file path, assign no Program number, use the neutral receiver, complete the campaign through visible actions, export the changed run, clear the holder context, import it, and resume exactly.

No bespoke Orchard theme, source inspection, receiver, role mapping, or trust claim is permitted. A general defect exposed by the Orchard may be repaired only through a general regression that applies to every cartridge.
