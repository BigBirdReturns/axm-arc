# The Lamp District acceptance contract

**Authority:** *The Godscar Codex, Book II: The Dark Tomb*, first recension, and the RODOH 1.0 Gate 3 release train.

The Lamp District is the first canonical `dark-tomb-pocket/1` reference. Gate 3 is accepted only when the same creator source can be edited, validated, compiled, installed, completed, inspected, exported, and recovered without a receiver inventing Tomb state or bypassing the ordinary Arc engine.

## Canonical artifacts

- `src/dark-tomb/lamp-district.ts` is the code-level source authority.
- `cartridges/lamp-district.tomb.json` is the editable portable source artifact.
- `src/arcs/lamp-district.ts` exposes the compiled bundled Arc.
- `cartridges/lamp-district.arc.json` is the exact portable compiled artifact.
- `npm run build:dark-tomb-reference` deterministically rebuilds both JSON artifacts.

The source and compiled artifact must remain exact under tests. Product parity rebuilds them from code authority and requires a clean Git diff before campaign or production-build claims can pass. Same-id replacement, receiver-authored defaults, and lossy recovery are not permitted.

## Campaign path

The canonical movement sequence is:

```text
keep the school lamps
→ authorize the reservoir route
→ cross the drainage liturgy
→ read the sleeping market
→ wake the war lattice
→ interrupt the surface sacrifice
→ return with heat
→ redraw the district map
```

The first two movements establish ordinary civic life and authority. The next two cross the quiet works and historical strata. The breach movements confront the dormant search lattice and the policy that sacrifices surface households. The return movements distribute recovered heat and rewrite the public map rather than resetting the hub.

## Persistent inheritance

A completed run must leave these engine-owned facts:

- Alarm phase `wake`;
- signature status `breached`;
- visibility status `exposed`;
- school-lamp rationing recorded as a constituency;
- a bounded reservoir charter;
- the drainage route reopened;
- sealed-market witnesses restored to the map;
- the Alarm audit opened;
- surface households recognized as citizens;
- clinic heat treated as a commons;
- a public depth map inherited by the next expedition.

The report receipts and cycle event stream must name every state transition with the authored reason, prior value, resulting value, challenge, outcome, and cycle.

## Authoring path

The Dark Tomb Forge provides two views over the same creator source:

1. **Guided source** for identity, pressures, evidence, Long Alarm, signature budget, layers, depth, cast, consequences, delves, expedition ledgers, and Story Physics.
2. **Exact JSON** for direct repair and complete custody.

The Forge must be able to start from the private Book II seed or load The Lamp District, preserve a local exact draft, validate and compile through the registered source plane, run a bounded deterministic campaign sweep, install the compiled Arc, export both source and Arc, and open the compiled cartridge in the ordinary player.

## Automated acceptance

Gate 3 requires:

- strict source validation and exact source recovery;
- equality between code authority and both portable artifacts;
- deterministic artifact digest;
- registered source-plane compilation;
- a multi-seed full-campaign sweep with zero gate violations and no engine warnings;
- completion from the exact named founding cast;
- exact final Tomb-state inheritance;
- Forge source, draft, compile, refusal, install/export seam, and bounded playtest tests;
- complete Arc test and product-parity workflows;
- production build from the exact accepted head.

## Boundary

Gate 3 completes the Arc-side canonical Dark Tomb cartridge and authoring product. A dedicated World underworld representation, spatial hub, layered map, production art set, and desktop/mobile browser journey remain Gate 4. Gate 3 does not authorize World to duplicate the Tomb compiler, state effects, composition law, or campaign resolution.
