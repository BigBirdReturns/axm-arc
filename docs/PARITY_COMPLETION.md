# AXM local-first product parity — inventory, sequence, completion contract

**Scope:** the shipped browser products in `axm-arc` and `axm-world`, the three
bundled reference cartridges, their local custody loop, their current
representations, authoring surfaces, responsive layouts, local vector/pixel art,
and accessibility/sensory controls.

Parity does not mean every cartridge has identical fiction or identical mechanics.
It means every supported product path meets the same dignity floor and every
intentional difference is authored rather than accidental.

## 1. Inventory

| Plane | Required completion evidence |
|---|---|
| Engine | deterministic resolution; schema refusal; complete campaign reachability; no access bypass |
| Custody | content identity; exact `axm-cartridge-run/v3` export/import/resume; unknown extension preservation; offline operation |
| Player loop | cold entry; authored opening; real engine-honored action; legible result; persistent consequence; return/resume |
| Representations | Board, Map, Hall, Encounter, Aperture, and Globe all read one run and remain reachable on desktop/mobile |
| Cartridge identity | owned role bodies/portraits, challenge motifs, emblem, material treatment, and procedural globe palette for every bundled cartridge |
| Waking Tower authority | player-facing name and original fiction; compatibility-only `karazhan` id; Arc and World pointers governed by `docs/WAKING_TOWER_DESIGN_AUTHORITY.md` |
| Authoring | Library, Workshop, functional Designer sections, Godscar guided/source editor, validation, simulation, install, export |
| Authoring QA | role/check coverage surfaced; specialist attributes explicit; cosmetic/dead attributes treated as structural warnings |
| Accessibility | keyboard-visible focus, 44px mobile target floor, EN/zh-Hant chrome, reduced motion, forced-color/high-contrast fallback |
| Sensory | local persistent sound/motion preferences and optional procedural cues with no media dependency or run-state mutation |
| Regression | dedicated Arc and World parity workflows plus full existing suites and production builds |

## 2. Gap sequence

1. **Truth first.** Keep deterministic execution, gates, save/custody, and
   evidence invariants green before changing expression.
2. **Finish authoring.** Remove dead Designer navigation; expose items,
   challenges, exact Arc records, and structural coverage; turn Godscar Forge
   from a raw textarea into guided and source views over one canonical object.
3. **Equalize cartridge expression.** Give First Charter and The Waking Tower the same
   white-label appearance dignity already established by Ilyon and extend all
   three identities across every shared representation.
4. **Equalize journeys.** Exercise every bundled campaign through World
   projections and exact custody, then cover first-action representation parity
   in desktop and mobile Chromium.
5. **Close sensory/accessibility drift.** Put persistent sound and motion
   controls on entry, play, and every standalone authoring/record surface.
6. **Make completion durable.** Add focused parity workflows and governed
   docs/assets so future work cannot quietly reintroduce a lower-quality lane.

## 3. Completion decision

The local-first browser scope is complete when both repository parity workflows
and both normal suites pass on their reviewed heads, when every bundled
cartridge carries original player-facing fiction, and when World pins the
accepted Arc source exactly. A missing external service cannot be smuggled into
that claim because this scope deliberately requires no external service.

The Waking Tower name, compatibility id, source pointers, accepted World projection, and Dark Tomb exclusion are governed by `docs/WAKING_TOWER_DESIGN_AUTHORITY.md`.

## 4. Explicit future products

The following are valuable expansion products, not hidden blockers for the
scope above:

- multiplayer and real-time netcode;
- cloud identity, account sync, and hosted convenience;
- marketplace economics;
- cryptographic publisher signing/certification;
- cinematic video, orchestral score, and high-resolution painted illustration;
- authored-content translation packs beyond the bilingual runtime chrome.

Those capabilities require new contracts, infrastructure, or content. Their
absence does not lower the completed deterministic, portable, local-first
product into a prototype.
